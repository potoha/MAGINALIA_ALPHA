# Sprint 2026-W35

Dates: 2026-08-24 → 2026-08-30  
Status: Active

## Primary Outcome

**Quote Capture で端末内に確定した pending capture を、portable data を汚さず `.magicap` として MAGINALIA IDE へ受け渡せる producer boundary を成立させる。**

## Why now

W34 では canonical contract と product boundary の整理を先行した。W35 ではその境界を壊さず、実際のスマートフォン利用で「撮る → 人が範囲を決める → 後工程へ渡す」最小 vertical slice を先に通す。

ここで Quote Capture 内部の working state と IDE 側の canonical data を直接結合しないことで、OCR engine、IDE、Git/GitHub、公開処理を後から独立して交換・拡張できる状態を維持する。

## User

PCやGitに詳しくない文系学生・研究者・書き手。スマートフォンで本を読みながら、引用候補をその場で素早く確保したい利用者。

### Producer contract at close

A W35-2 package is an explicit Capture handoff artifact:

```text
<isbn13>.magicap
  manifest.json
  captures/<capture-id>.json
  images/<page-id>.<ext>
```

The current producer contract includes:

- format: `maginalia-capture-package`
- version: `1`
- mandatory fresh `packageId` using the `capkg:<Crockford ULID>` form
- book ISBN-13
- capture count
- capture metadata including selected region, nullable page number, comment and pending OCR status
- source page image references and de-duplicated image payloads

`.magicap` is the logical filename; the current media type remains `application/zip`.

### Known limitations accepted at close

- Browser Blob URL + `download` attribute is the current export transport.
- Normal mobile browsers can download `<isbn13>.magicap`.
- LINE MINI App WebView may suppress Blob downloads.
- W35-2 does **not** include a LINE-specific share/save fallback.
- W35-2 does **not** include server upload transport.
- A file manager may visually classify `.magicap` as ZIP because the MIME type is `application/zip`.
- IndexedDB state created inside LINE WebView cannot be assumed to migrate to an external browser.

These are producer/UI egress limitations. They are not permission to weaken the IDE parser or silently accept arbitrary ZIP files.

### Handoff to the next IDE packet

The producer boundary is closed. The next packet starts from an untrusted `.magicap` input and must preserve that distinction.

Required carry-over:

1. Use an explicit `.magicap` file-picker/import path. Do not infer arbitrary ZIP files as Capture Packages.
2. Validate the v1 manifest, including mandatory `packageId`, before treating package content as a Capture handoff.
3. Retain each capture's source image, normalized selection, page number, comment and pending status for preview/OCR review.
4. Treat imported package contents as **untrusted, read-only handoff input**.
5. Import alone must not create Canonical Annotations.
6. Import alone must not create Research Project files, durable inbox state, Git commits, GitHub writes or publication state.
7. OCR output remains a draft until a human explicitly verifies/corrects it.
8. Capture UUIDs and raw ISBNs must be adapted deliberately at the canonicalization boundary rather than silently relabelled.
9. LINE WebView download failure is a Capture egress problem, not a reason to add IDE persistence or relax validation.
