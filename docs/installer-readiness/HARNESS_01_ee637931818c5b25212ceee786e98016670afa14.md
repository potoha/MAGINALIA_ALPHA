**Audit type:** read-only readiness review; no product implementation was performed during the audit.
**Follow-up validation:** the existing quotation Electron smoke was rerun and its filename assertion corrected in `af1c2624cfaa3ead2560d6809f67e3c47337c2ed` after the audit found the smoke was matching an icon-prefixed label rather than the file-name data field.

## Decision and scope

**Installer Readiness Gate: `READY_AFTER_TARGETED_REMEDIATION`.**

The current architecture has suitable boundaries for a Windows distribution: Electron main/preload/renderer builds, D068 folder identity, Repository Core templates, Workdesk registration, isolated user data, and a loopback Reviewer service. It is not ready to package as-is. The missing installer, bundled Reviewer runtime, offline PDF/DOCX tools, first-run coordinator, and safe tutorial materializer are direct items in the authorized distribution request. They are bounded implementation work inside that request, not reasons to broaden into unrelated cleanup. No architecture-level dead end was found in the inspected boundaries.

This is an installer-readiness audit, not a claim that the whole I1 release-maintenance program or any installed-product acceptance is complete.

## Raw findings

| ID | Raw observation |
|---|---|
| R01 | There is no Windows installer build configuration or installer artifact script. |
| R02 | The packaged app would not currently have an explicit `productName`, stable Windows `appId`, or installer shortcut/upgrade/uninstall policy. |
| R03 | The default Reviewer strategy depends on a source-tree sidecar plus a development Python environment or `uv`; no frozen Reviewer executable is produced or selected by `main.ts`. |
| R04 | The packaged Reviewer needs its versioned sidecar contracts. A packaged `contractsDir` hook exists but production main does not pass it. |
| R05 | PDF and DOCX exports can resolve tools through the developer's PATH/configuration; an installed machine without those tools is not supported by the current runtime selection. |
| R06 | First-run Workdesk creation, Private Shelf selection/creation, Tutorial seed application, Tutorial Project registration, Downloads image placement, interruption recovery, and completion routing are not orchestrated by a first-run service. |
| R07 | The tutorial manifest describes add-only/conflict behavior, but no runtime materializer enforces those rules against a non-empty Shelf. |
| R08 | The configured Shelf boundary can open an existing Private Shelf; no explicit shelf creation operation exists. Public Shelf is only represented as configuration data and has no user-facing registration flow. |
| R09 | The app has no stable “open bundled offline manual” entry point or manual packaging slot. |
| R10 | `LICENSE`/`NOTICE` are present, but a strict package allowlist and shipped-dependency notices are absent. |
| R11 | The managed Reviewer receives `MARGINALIA_REVIEWER_ENABLE_LEGACY_GITHUB=0`; legacy GitHub publication code remains in the sidecar source. D032 remains frozen. D059’s earlier active-tree cleanup timing conflicts with the latest Product Owner instruction deferring repository-wide cleanup to source-freeze. |
| R12 | The quotation Electron smoke initially failed because the test read a visible filename label prefixed by a document icon. The app opened the correct temporary Project, selected the Markdown file, and saved the expected text; reading the file-name data attribute made the smoke pass. |
